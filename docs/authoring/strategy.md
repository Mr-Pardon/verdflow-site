# 创作自己的策略

<p class="lead">把空间意图写成可解释、可复现、可调节的算法。</p>

## 1. 导出作者工具包

从策略库获取模板与 VFS Author Skill。优先使用与你的产品构建匹配的工具包，而不是凭本文手工拼一个未知版本的清单。

工具包外层使用 ZIP，方便打开阅读。完成后的策略按标准打包为 `.vfs`。

## 2. 写一份空间设计说明

明确种植范围、留白关系、连续或成团分布、角色职责，以及希望用户调整的参数。可以从已有样本提取特征，也可以直接设计新的空间算法。

样本只能作为证据，不能保证单个样本中的密度与尺度适用于所有地形。

先要求 Agent 解释[角色](./roles.md)，确认后再开始实现。不要把 DTS 资源名称硬编码成策略的角色定义。

## 3. 实现生成规则

算法接收标准区域、参数和随机种子，生成带角色的标准点位。遵循模板的入口与输出约束，保持目标输出侧独立。

至少保证：

- 坐标与数值有限，角色键属于清单声明。
- 点位在约定的区域关系内，正确处理孔洞与边界。
- 相同输入和种子可复现，不偷偷依赖当前时间。
- 不把模型资源定位、DTS 调用或 XML 写入放进策略算法。
- 退化、小面积和狭窄区域有可解释处理，不静默产生错误结果。

## 4. 暴露少量有用参数

优先暴露用户能解释的间距、覆盖比例、退让、斑块尺度等参数。清楚写明单位、默认值、范围、步长与作用。

不要把所有实现常数都变成面板控件。基础设置解决主要效果，高级设置用于确有必要的细调。

需要让参数随用途开关隐藏时，使用参数的 `visible_for_roles` 声明，不让应用猜参数名。任一关联用途启用就显示；隐藏不删除参数值，也不替代生成器自己的构图判断。

为角色添加用途分组、推荐植被与包内静态示意，帮助用户理解如何选材。资料跟随 `.vfs` 分发，修改资料同样改变包内容，需要重新导入与信任。声明格式见[角色与用途说明](./roles.md#为用途补充示意与推荐)。

## 5. 验证，而不是只看一张图

可以在 `extensions.parameter_preview` 中声明一个固定的本地米制、无孔洞样本边界和种子，让 Studio 与实时面板调用原生成器展示参数变化。不需要另写预览算法，也不需要策略读取资产半径或调用 DTS。

样本只是可选的解释工具，不能替代正式验证。它有独立的顶点、面积、点数与执行时间预算；具体声明和约束见最新版 VFS Author 的参数预览说明。保持点位 ID 稳定有助于应用显示搭配参考范围。

至少测试简单面、凹面、带孔面、小面、窄面及大范围。比较固定种子的重复结果，再测试不同种子的变化。

检查点位数量、越界、重叠、耗时和角色之间的关系。视觉检查与数值检查都需要做；漂亮的概念图不是算法验证。

还要验证不同角色开关组合。策略可以按关闭角色改变剩余构图，但必须说明规则，并保证固定几何、精确包、参数、种子与开关时可复现；不必无条件承诺与完整生成后过滤等价。

## 6. 导入与搭配

打包 `.vfs` 并导入策略库。审阅代码来源，确认信任后建立对应版本的植被搭配，在小范围执行真实测试。

模型缩放与真实尺寸可能改变视觉观感。策略点位合理，不代表任意植被映射都不会穿越边界。

## 给 Agent 的开场要求

```text
请先阅读 VFS Author Skill 和模板，暂不写代码。
先解释我想要的空间关系，为每个角色说明职责和可替代植被，
区分角色与具体树种。确认最小角色集合后，提出参数与验证方案。
实现必须满足标准入口、固定种子复现、区域边界和孔洞约束。
最后交付可导入策略包、测试结果，以及尚未验证的限制。
```

这不是绕过模板约束的提示词。完整规范始终以导出的 Skill 与模板为准。
