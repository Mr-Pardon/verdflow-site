# 输入数据检查

## 按输入路线核对

| 数据 | 最重要的检查 |
| --- | --- |
| FBX | Blender 能读取，材质与绿地对应，面在 XY 上有有效面积 |
| SHP | 必要伴随文件齐全，面几何有效，数值为预期的米制坐标 |
| GeoJSON | Polygon / MultiPolygon，坐标与高程数据对齐 |
| 高程 GeoTIFF | 高程有效、覆盖区域，无关键 NoData 缺口；影像路线使用单波段高程 |
| RGB GeoTIFF | 可见光 RGB 整数像素值在 0–255，与单波段高程使用同一米制投影；见[影像识别种植](../workflows/imagery.md) |
| DTS 实时选区 | 地形已加载，面或开放折线与所选策略匹配，目标资源存在 |
| DTS 场景绿地构件 | 用于[拾取绿地](../workflows/live.md#pick-green-space)的绿地面应单独合并为构件；与道路或铺装混合时，非种植区域可能被一同提取 |

## SHP 不是一个孤立文件

```text
planting.shp    几何
planting.shx    索引
planting.dbf    属性
planting.cpg    可选编码说明
planting.prj    可选坐标描述
```

文件保持同名并放在同一目录。实时路径导入 ZIP 时，将所需文件一起打包；不要把伴随文件分别重命名。

`.prj` 可以携带描述，但不会触发 VerdFlow 自动投影转换。

## 实时 SHP 导入要求 {#实时-shp-导入限制}

实时面板直接将 SHP 面加入当前 DTS 场景的选区列表。与[项目式地理空间路线](../workflows/geospatial.md)不同，不直接接收 GeoJSON，也无需另选高程 TIF。

| 项目 | 要求 |
| --- | --- |
| 格式 | `.shp` 或包含单套 SHP 数据的 `.zip`；不直接接收 GeoJSON |
| 几何 | 有效且面积大于零的面；多部件拆开，保留有效孔洞 |
| 必要文件 | 同目录、同名的 `.shp`、`.shx`、`.dbf`；`.cpg` 可选 |

**1.2.1 起**，实时面板分批加载 SHP 选区，不再沿用早期版本固定的文件大小、累计顶点和草稿总量限制。实际可处理规模仍取决于数据复杂度、可用磁盘与内存、Explorer 场景等条件。

格式或几何不符合要求时，本次导入会失败，不会先导入一部分再静默跳过。这与执行时隔离单面高程失败是两回事。

范围很大时，先用一部分数据核对坐标、边界和种植效果。也可在 GIS 工具中拆分数据，或改用工作台处理并准备 GeoTIFF 高程。

## 坐标与单位

区域 XY 与高程栅格使用相同的米制坐标空间。需要转换投影或单位时，在 GIS 或模型工具中预先完成。

GeoJSON 并不天然意味着米制坐标。常见地理经纬度数据不能直接用于以米计算间距的策略。文件扩展名正确，不代表空间数值正确。

## 面的几何

种植区域需要有效的面，而不是一组看起来围成面但未闭合的线。注意自交、重复点、零面积外环、孔洞关系及非常狭窄的退化区域。

FBX 中一个面可能是竖直面，三维面积存在但投影到 XY 后为零。遇到“usable XY area must be positive”，应检查这个问题，而不是只增大超时。

## 高程

检查区域是否落在 GeoTIFF 有效范围内。边缘缺口、NoData、无穷值或把非高程波段当作高程，都会影响后续输出。

DTS 实时采样依赖场景地形的可用性。空间窗口会帮助加载附近地形，但不保证未加载、缺失或异常地形能返回正确结果。

## 大数据

面数量、顶点数量、区域面积和点位密度共同决定成本。几何面数量很少，也可能因边界顶点极多而让交互与提取变慢。

先用小范围确认整条链路，再处理大范围。当前不承诺自动合并相邻面或自动把所有数据切成可交付种植批次。
