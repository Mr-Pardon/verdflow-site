# 输入数据检查

## 按输入路线核对

| 数据 | 最重要的检查 |
| --- | --- |
| FBX | Blender 能读取，材质与绿地对应，面在 XY 上有有效面积 |
| SHP | 必要伴随文件齐全，面几何有效，数值为预期的米制坐标 |
| GeoJSON | Polygon / MultiPolygon，坐标与高程数据对齐 |
| GeoTIFF | 第一波段为可用高程，覆盖区域，无关键 NoData 缺口 |
| DTS 实时选区 | 地形已加载，面轮廓可见，目标资源存在 |

## SHP 不是一个孤立文件

```text
planting.shp    几何
planting.shx    索引
planting.dbf    属性
planting.cpg    可选编码说明
planting.prj    可选坐标描述
```

文件保持同名并放在同一目录。实时路径导入 ZIP 时，将所需文件一起打包；不要把伴随文件分别重命名。

`.prj` 可以携带描述，但不会触发 VerdFlow 自动投影转换。

## 实时 SHP 导入限制

以下为 VerdFlow 1.0.0 实时面板的导入保护限制，不是项目式 SHP / GeoJSON + GeoTIFF 路线的统一上限，也不是建议一次种植的规模。

| 项目 | 当前规则 |
| --- | --- |
| 格式 | `.shp` 或包含单套 SHP 数据的 `.zip`；不直接接收 GeoJSON |
| 几何 | 有效且面积大于零的面；多部件拆开，带孔洞面拒绝导入 |
| 必要文件 | 同目录、同名的 `.shp`、`.shx`、`.dbf`；`.cpg` 可选 |
| 文件体量 | 64 MiB；直接导入按数据文件检查，ZIP 同时检查压缩文件及解压后文件总量 |
| ZIP 文件数 | 不超过 1,000 个文件，且只包含一份 `.shp` 数据集 |
| 顶点总量 | 不超过 100,000 个 SHP 原始顶点，闭合端点也计入 |
| 导入后的选区数据 | 序列化结果还需处于约 30 MiB 的传输保护范围内 |

文件格式、几何或体量不符合要求时，本次导入会失败，不会先导入一部分再静默跳过。这与执行时隔离单面高程失败是两回事。

超限时在 GIS 工具中按工作范围拆分文件，必要时在检查轮廓后简化顶点。含孔洞的数据可使用支持孔洞的项目式地理空间路线并配备 GeoTIFF，或在上游明确拆成保留排除区域的无孔面；不要直接删除孔洞来绕过限制。

## 坐标与单位

区域 XY 与高程栅格使用相同的米制坐标空间。需要转换投影或单位时，在 GIS 或模型工具中预先完成。

GeoJSON 并不天然意味着米制坐标。常见地理经纬度数据不能直接用于以米计算间距的策略。文件扩展名正确，不代表空间数值正确。

## 面的几何

种植区域需要有效的面，而不是一组看起来围成面但未闭合的线。注意自交、重复点、零面积外环、孔洞关系及非常狭窄的退化区域。

FBX 中一个面可能是竖直面，三维面积存在但投影到 XY 后为零。遇到“usable XY area must be positive”，应检查这个问题，而不是只增大超时。

## 高程

检查区域是否落在 GeoTIFF 有效范围内。边缘缺口、NoData、无穷值或把非高程波段当作高程，都会影响后续输出。

DTS 实时采样依赖场景地形的可用性。空间窗口会帮助加载附近地形，但不保证未加载、缺失或异常地形能返回正确结果。

## 大数据

面数量、顶点数量、区域面积和点位密度共同决定成本。几何面数量很少，也可能因边界顶点极多而让交互与提取变慢。

先用小范围确认整条链路，再处理大范围。当前不承诺自动合并相邻面或自动把所有数据切成可交付种植批次。
