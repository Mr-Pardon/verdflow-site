# 数据备份与更新

## 需要保留两个位置

| 位置 | 主要内容 |
| --- | --- |
| `%LOCALAPPDATA%\VerdFlow` | Library、system-config、Logs、Electron 等用户数据 |
| 创建项目时选择的目录 | 项目状态、输入与运行产物、点位及保留的 XML |

软件解压目录不再承担用户数据根目录。更换便携包时，不应把“旧软件目录”和“全部用户数据”混为一谈。

## 备份步骤

1. 等待当前任务结束或明确取消，退出 Studio。
2. 复制完整用户数据目录到备份位置。
3. 复制需要保留的项目目录。
4. 对关键交付 XML 另外保存副本，并使用可识别的文件名。

可以额外导出 `.vfs`、`.vfa`、`.vfp`，用于独立交换与核查。但它们不能代替完整项目备份。

## 凭证

模型服务等 API 凭证由 Windows 系统凭证存储管理。普通文件夹备份不保证能迁移所有密钥，跨电脑使用时应重新配置与验证连接。

不要把凭证、完整日志中的敏感内容或私人路径放进公开 GitHub 仓库。

## 在应用内更新

便携版在 **设置 → 应用更新**中提供版本检查与下载：

1. 更新前按上文备份用户数据和项目。
2. 点击 **检查更新**，查看较新的稳定版本。默认开启自动检查和发现更新后自动下载，可按需要关闭。
3. 若未自动下载，点击 **下载更新**；下载时可以取消。软件会校验更新包并准备文件。
4. 等当前任务完成或明确取消，并在 **多源工作台 → DTS**停止实时服务。只关闭实时面板不等于停止服务。
5. 准备就绪后点击 **重启并更新**。下载完成不会未经确认自动重启。

更新替换程序，不替换统一用户数据目录或项目目录。程序所在目录需要可写，并有足够空间准备更新与旧程序备份。保留旧程序不等于能自动回退所有数据格式，升级前仍应阅读版本兼容说明。

没有可用更新入口的版本请手动更新。新版正常启动后会清理经核验的旧程序备份；请另外保留自己备份的项目和用户数据。

## 手动更新便携包

无法联网更新或当前运行方式不提供更新入口时，可从 [GitHub Releases](https://github.com/Mr-Pardon/VerdFlow/releases)下载完整便携包。先备份，结束任务并退出旧程序，再将新版本解压到新的软件目录并启动，不要混合新旧程序文件。同一 Windows 用户下的软件会使用统一用户数据目录。

更新前阅读目标版本的兼容说明；涉及项目或资源格式变化时，按对应迁移步骤操作，并保留升级前的备份。

检查或下载失败时，不要删除用户数据来重试。先检查网络、磁盘空间与目录权限；只有明确完成更新，才能把新版本视为已安装。

## 删除与移出项目列表

删除有效 VerdFlow 项目会包含本地项目文件，应认真核对二次确认中的目标目录。

如果记录对应的目录不是当前可识别的 VerdFlow 项目，点击该卡片的删除入口时，确认框应显示 **移除项目记录？**，操作按钮为 **移除记录**。此时只清理列表记录，不删除原目录和文件；若看到 **删除整个项目？ / 永久删除**，应先取消并核对目标。

对文件身份不确定时，先备份并查看目录结构，不要尝试强制删除。
